# Evaluation collection

The product embedding, synchronous LLM and streaming LLM adapters require a durable budget reservation before each outbound attempt. Configure `KNOWFLOW_BUDGET_LEDGER_PATH`, `KNOWFLOW_BUDGET_PRICE_FILE` and `KNOWFLOW_BUDGET_POLICY_FILE` in every service process, with the same ledger path on the same host. The ledger uses integer microyuan and SQLite write transactions. A reservation is rejected if it would take the cumulative total over RMB 8, and no new reservation is accepted once the total reaches RMB 8. Reservations exceeding RMB 10 are rejected. Failed calls retain reservations and retries use new reservation IDs.

Price and policy files are JSON objects keyed by the exact model name. Each price contains `provider`, `model`, `input_cny_per_million`, `output_cny_per_million`, `source_url`, `verified_by`, `verified_at` and `valid_until`. Prices use decimal strings and CNY per million tokens. Each policy contains `provider`, `bound_kind`, `source_url`, `verified_by`, `verified_at`, `valid_until`, `input_tokens_upper`, `output_tokens_upper` and `max_payload_bytes`. The supported bound kind is `provider_context_limit`. A qualified reviewer must supply trustworthy model-context bounds and their validity period before enabling real calls. Configuration errors are rejected before HTTP requests. Reserved amounts are conservative and are reported separately from actual provider billing.

Dry-run a JSON array of reservation inputs with `python evaluation/collector/estimate.py requests.json`. Each entry contains `request_id`, `provider`, `model`, `input_tokens_upper`, `output_tokens_upper` and `quote`. Include an entry for every planned indexing batch, query embedding, generation and retry. The command uses a temporary ledger and outputs cumulative reservations and the first rejected operation. A stopped plan returns exit code 1.

`create_evaluation_app` accepts validated service settings, a `BudgetLedger`, embedding and LLM factory configurations, and an independent `control_secret`. Factory configurations include `adapter_factory`, `provider`, `model`, `quote`, `token_bounds` and `bound_evidence`. Missing settings or invalid guards raise `EVALUATION_SERVICE_NOT_READY`. Its local capture endpoint additionally requires the normal internal bearer credential and `X-Evaluation-Secret`. Captures are single-use and intended for synchronous collection.

Use `python evaluation/collector/run.py --dataset DATASET --split development --output PREDICTIONS --run-metadata RUN_METADATA` against already running local Java and evaluation AI services. Runtime credentials are read from `KNOWFLOW_EVALUATION_ACCESS_TOKEN`, `KNOWFLOW_EVALUATION_DATABASE_URL`, `KNOWFLOW_INTERNAL_SHARED_SECRET` and `KNOWFLOW_EVALUATION_CONTROL_SECRET`. The database identity must be authorized to read indexing version IDs and question records. The access token must belong to the evaluation owner. Run metadata requires `code_sha`, `schema_sha256`, `config_sha256`, `prompt_sha256` and `model`. Use actual implementation, schema, configuration and prompt fingerprints.

The collector creates and deletes its own knowledge base, uploads the exact dataset bytes, waits for successful indexing, verifies source hashes, correlates captures with Java question rows, checks public citation mapping and writes runner v2 predictions. A companion `.status.json` records indexing and question budget snapshots, incomplete samples and cleanup failures. Collection errors return a nonzero exit code. Human review and quality-gate evaluation follow through the existing runner commands.

Run `python scripts/e2e-evaluation.py --output REPORT` to verify the full Java/PostgreSQL/MinIO/Python path with deterministic fake providers. It generates temporary credentials and a unique Compose project, refuses occupied service ports, blocks external HTTP in the fake AI service, collects the public seed development split and verifies resource cleanup. The fake ledger values describe simulated reservations. The workflow runs this smoke test in the `evaluation-e2e` job.

`python evaluation/adapters/private_pack_to_runner.py` converts a locally authorized private pack into `.blindtest/out/runner`. It validates commitments and Unicode offsets and refuses existing output or path escape. It prints only counts and a dataset hash. Its implementation tests use synthetic packs. Public seed validation retains its original counts and coverage requirements. Local private packs use their own 20-question, 15-answerable/5-unanswerable validation and retain their source licensing metadata.
