- 对应任务：KF2-001/004；前置 KF2-001 新基线范围决策获用户批准并待 Q，B 的 KF2-002/003 和 M 的 KF2-005 已提交待审。
- 作者：Codex-A；日期：2026-10-30（Asia/Hong_Kong）。
- 基线：V0.2 计划 `7d5095b`、B/M 交付 `origin/python@928b5d9`；原 V1.1 缺失且明确不阻断新基线。

## 动机与所有权

Java 负责用户、知识库、文档、内容版本、任务、租约、活动索引、问答历史和清理计划的业务写入。Python 负责解析、分段、Embedding、检索、生成及受限候选索引写入，不发布活动版本。Flyway 和公共契约由 A 单写，Compose/CI/根配置由 M 维护，AI 服务与评测由 B 维护。

## 状态提议

| 对象 | 候选状态 | 重要不变量 |
|---|---|---|
| 文档 | ACTIVE、DELETED | 文档可见性与索引处理状态分开；重建失败不隐藏旧活动索引；DELETED 不可被回调恢复 |
| 索引版本 | BUILDING、READY、FAILED、RETIRED | 完整性验收前不可检索；READY 后内容不可变；活动指针只由 Java 切换 |
| 任务 | QUEUED、RUNNING、SUCCEEDED、FAILED、CANCELLED | 只有一个有效执行租约；重试通过显式尝试计数和新 fencing；终态不可被不同结果覆盖 |
| 问答 | RUNNING、SUCCEEDED、FAILED、CANCELLED | 记录每次独立问题；失败/部分输出与成功区分；历史来源依当前权限访问 |

索引 READY 表示完整候选已经通过验收，不代表它必然是当前活动版本。重复内容的幂等身份为文档 + 内容版本 + 流水线配置版本；显式重建若允许同一组合多次执行，还需 generation/请求幂等键，冻结前定义约束，不抢先写迁移。

## 索引执行与事务边界

1. 上传对象与数据库不能用单个本地事务保证原子：Java 记录可追踪的暂存对象/补偿清理；文档、候选版本与任务在数据库事务中关联。孤立对象有回收途径。
2. Java 用数据库行锁或等价原子条件更新领取任务；递增 fencing 值，生成不可猜测执行令牌，只存哈希并设置期限。提交后调用 Python；派发失败进入同一租约/重试流程。
3. Python 每批写入候选索引都必须受到任务、版本与执行上下文限制。旧执行不能写新租约数据或已发布版本。单纯以服务角色授予整张表写权限不能满足这一要求；受控 SQL/网关方案留待 B/Q 确认。
4. 心跳只接受当前有效身份，服务器决定续期。过期任务不能通过迟到心跳自我复活；重试新建执行身份但不改变内容版本。
5. 完成回调先鉴别服务和执行身份，再锁定/核验文档、任务、候选版本及 fencing。Java 直接核验持久化索引的数目、维度、内容/流水线对应、完整性及无残留失败批次；不把 Python 自报的 count/hash 当作验收证据。
6. 验收、任务成功、结果去重记录与活动版本切换在同一事务中提交。失败重建保持旧活动指针。与删除使用一致锁顺序或等价串行约束，防止先检查再无条件发布的竞态。
7. 删除事务先撤销文档/知识库可见性、失效当前任务及执行身份，再安排幂等清理；异步清理失败不逆转删除。旧 Worker 与重复回调均不能重新激活。

完成重放的具体错误优先级、当前租约与已接收结果的区别见 [API 草案](../../contracts/api-draft.md)。事务内的验收与发布不能分成“任务先成功、稍后切换”而留下半完成状态。

## 检索、删除与历史

Java 由当前认证主体生成单一知识库的可信活动版本快照，Python 在 SQL 中执行同样的 owner/知识库/文档可见性/活动版本约束。切换后的新请求只接受新版本；切换前已接收请求可使用旧快照，需要引用保留或请求 pinning 防止提前清理。

生成完成和每次 SSE 发送前，Java 再核验资源可见性。删除导致后续输出停止。已经发送的内容无法撤回；实现需记录删除提交与输出检查/写出的并发边界，并进行真实竞态验证。

历史答案可保留已显示文本，但旧来源永远绑定原版本，不重定向到新版本冒充原证据。来源已删/已清理时返回失效状态，不携带片段或对象路径。所有引用、文件、历史入口独立重新鉴权。

## Flyway 编号规则（提议）

- A 统一分配递增版本号；正式迁移放在 `services/api/**/db/migration/`，格式 `V<序号>__<描述>.sql`，具体起始号等待原迁移历史核对。
- 已发布迁移不可重写；升级以新版本追加；分配前核对集成分支与其他待合并迁移，避免版本碰撞。
- B 提交向量表/维度/数据库角色需求；A 落地；Q 检查最小权限、迁移及升级证据。运行服务不用超级用户或迁移角色。
- 不提前固定模型维度、不自动清库、不用新迁移覆盖未知的旧设计。
