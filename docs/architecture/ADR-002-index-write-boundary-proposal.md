# ADR-002：候选索引写入边界提案

- 状态：`PROPOSED`；等待 B 消费需求及 Q 审阅，不是已接受的跨服务协议。
- 对应：JP-01 JP-A1 / JP-C1；KF2-011 与 KF2-018 交接。
- 作者：Codex-A；日期：2026-10-30（Asia/Hong_Kong）。
- 基线：`150cd847a5750143fb6eb2c74c762962381952fe`。

## 提案

Python 使用 `knowflow_ai` 只读角色访问检索所需的知识库、文档、内容版本、索引版本、Chunk 和向量；该角色不得更新任务/文档状态，也不得直接插入或修改 Chunk/向量。当前 Flyway 初始迁移只给 `knowflow_ai` 这些表的 `SELECT` 权限。

KF2-018 的 Python 索引流水线通过 Java 内部的有界批量写入接口持久化候选索引。Java 在同一事务内核对服务凭证、文档及内容版本归属、候选索引处于 `BUILDING`、当前任务租约、执行令牌哈希、租约有效期和 fencing 值，然后写入有明确上限的 Chunk/向量批次。批次身份与规范化摘要用于幂等重放；不匹配的重放拒绝。完成完整性验收和发布仍由 Java 完成，旧 Worker 不得写入已发布或已替换的索引版本。

该方案让 Python 不持有应用数据库密码，并把状态核对与候选写入放在 Java 可信边界。它需要 B 确认批量数据形状、上限、重试和清理需求，再由 Q 审阅交易竞态及权限。未经上述确认，本迁移不开放任何无约束 AI 写权限，也不声称 KF2-018 已获准开发。

## 现有验证边界

KF2-011 候选迁移建立用户、知识库、文档、内容版本、索引版本、任务、Chunk 和 `vector(1024)` 结构；真实 PostgreSQL 测试覆盖空库迁移、重复迁移、唯一/外键/检查约束、AI 只读权限及应用角色无 DDL 权限。租约领取、fencing 写入、删除/发布并发和批次幂等尚无运行时代码或验收，本提案不把这些结构测试当作状态机证明。
