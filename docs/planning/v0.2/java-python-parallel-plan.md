## 4. 最小契约对齐：先局部开发基线，再正式冻结

当前共同起点是 `contracts/schemas/protocol.schema.json` 的 `0.2.0-draft.2`，原始 SHA-256 为 `edc9ada0bb5de23ddf69f96c9172b3fc3719f4b3111d5d35718f2717efae8087`。两端记录实际消费的提交及哈希，禁止同名版本静默修改语义。

第一批先对齐下列局部约定。这里是实施建议；新增部分由 A 合入契约并编号后成为双方开发输入，尚未变成生产冻结协议。

| 项目 | 本轮约定 / A 的交付 | B 的消费要求 |
|---|---|---|
| JSON 与版本 | 沿用 snake_case、带时区 RFC 3339，报文声明契约版本 | Pydantic 与 Schema 使用相同必填项、枚举和未知字段拒绝规则；不支持版本拒绝执行 |
| 内部认证 | 复用 `KNOWFLOW_INTERNAL_SHARED_SECRET`；Bearer 密钥需与现有 Java 的 32–256 字符规则一致 | 正确凭证允许内部访问；缺失、错误凭证 401；不得把服务认证等同于资源/执行授权 |
| 请求关联 | 沿用 `X-Request-ID`，Java 创建并透传；固定输入长度/字符限制 | 接收合法内部 ID 并回传；无 ID 时服务端生成；非法值不得原样写日志/响应 |
| 错误 | 沿用 `contract_version/request_id/code/message/retryable` | 将 FastAPI 的验证、认证、404/405 和异常处理统一映射；不把默认 422 或堆栈直接透出 |
| 健康 | Java 保留 `/actuator/health`；Python 建议 `GET /health/live` 与受认证的 `GET /internal/v1/health` | 只报告本服务状态，不返回环境值；内部 health 为本轮真实 Java→Python 联调入口，不触发模型/数据库请求 |
| 未实现业务 | 候选路径继续采用 `index-executions`、`answers` 等现有目录；在 A 的契约提交中明确当前启用路由 | 本轮不执行索引/检索/回答；未启用路由返回已约定不可用错误，不得伪造 202、任务完成或固定答案 |
| 模型 | `BAAI/bge-m3` / 1024 维，`deepseek-flash`；凭证选择器沿用现有环境变量名 | 适配器接口保留请求/返回 ID 匹配、维度、超时及脱敏语义；模型能力测试与服务健康分开 |
| 来源 | PDF 页码从 1 起；TXT/MD 原始文本 Unicode 码点偏移，从 0 起、右端不含 | 保留 document/content/index/Chunk 关联；检查 end>start，不能用渲染 Markdown 偏移或编造 PDF 坐标 |

A 对契约新增语义发布下一候选编号（例如 `0.2.0-draft.3`），同时更新 Java 常量、Schema、样例和版本说明；B 随同一提交更新消费者。不得要求 B 实现未发布的新字段。

**可以暂缓的完整契约内容：** SSE、取消路径、历史保留、公开登录凭证策略等不阻断本轮骨架/迁移工作；分别在对应业务任务实现前解决。当前版本只能登记为“局部开发消费已对齐”，不得把局部对齐写成 KF2-004 全部冻结或 M 已确认。

- 明确 Java 唯一拥有用户、授权、文档/任务状态和活动索引发布。B 的数据库身份不能直接更新这些表或列。

本轮无数据库环境时，可继续提交 SQL/配置候选和服务工作，但数据库验收保持未执行，不用 SQLite/Mock 代替 pgvector 和权限证据。
