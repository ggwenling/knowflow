# KF2-002：首轮试用与对照记录协议

状态：IN_REVIEW。本协议供项目负责人日后安排 3–5 位符合条件的参与者使用；本次未进行招募、访谈或真实试用。下方仅有合成材料及模拟试填，不是用户研究证据。

## 参与者、资料和隐私

- 招募条件：成年研发团队成员，承担开发、测试或维护工作，最近一个月查询过中文项目规范或 API 文档；不要求使用过 RAG 产品。
- 由负责人确认知情同意、参与者可随时退出，以及记录用途和保存期限。使用匿名编号 P01、P02 等；身份联系表（如负责人确需保留）与观察记录分开保存，不纳入仓库。
- 仅使用参与者获准使用的资料。原型如使用外部模型，开始前说明会发送哪些文本和供应商；未获授权时只用本文件的合成材料。
- 不记录姓名、雇主名称、客户资料、源码、密钥或未获准的原文。演示环境中出现的任何敏感信息立即停止并按负责人既定流程处理。

## 准备和操作步骤

1. 负责人选择同一份获准资料集，确认参考答案、有效版本、原文位置和权限；检查 KnowFlow 账号只含当前参与者可访问的个人资料。
2. 生成匿名编号。主持人说明目标是比较查找过程，答案正确且依据可核验才算成功；不评价参与者个人能力。
3. 按编号预先分配对照顺序：奇数编号先用其原有方法、偶数编号先用 KnowFlow。两种方法都做两题；先后次序和资料一致。记录顺序以便分析练习效应。
4. 每个任务最多 8 分钟。从主持人读出题目开始计时；最多给一次中性提示（“请继续用当前方法查找”），记录提示。到时仍未完成，记超时，不代答。
5. 参与者给出答案后，请其展示原文依据。记录答案、是否满足全部关键事实、来源路径/版本、依据定位时间、核验耗时、来源查看次数和异常。不得在完成记录前告诉其参考答案。
6. 两题结束后按下方访谈提纲提问。两周后只由负责人邀请参与者补记主动复用天数和任务数；没回访就标为未验证。

## 合成任务材料与评分键

以下内容是专供模板演练的虚构项目，所有限制仅属于该合成语料，不是 KnowFlow 产品承诺。

### 任务 A：索引任务 API 参数

**给参与者的题目：**“调用索引任务接口时，哪些请求字段必填？chunkSize 可以设为多少？单次等待时间上限是多少？请展示依据。”

**合成来源：** 虚构项目/API规范-v1.3.md，状态“已发布”，2026-09-15 生效。

> POST /v1/index-jobs。必填 JSON 字段：documentId（UUID）、profileId（字符串）。chunkSize 可选，默认 400，允许 200–800 的整数。waitMs 可选，允许 100–10000 毫秒。请求成功返回 202，并提供 jobId 供后续查询。

**评分键：** 三项关键事实均答对：必填字段为 documentId 与 profileId；chunkSize 为 200–800 且默认 400；waitMs 上限为 10000 毫秒。参与者还须指出 API规范-v1.3.md 的已发布原文。少一项、单位/范围错误、只报答案未定位来源均不算成功。

### 任务 B：冲突规范的有效版本

**给参与者的题目：**“重试等待时间应使用默认 20 秒、上限 60 秒，还是默认 10 秒、上限 30 秒？哪份规范当前生效？请展示能够判定版本优先级的依据。”

**合成来源一：** 虚构项目/重试策略草案-v1.2.md，状态“草案”，2026-09-20 编辑；建议默认 20 秒、上限 60 秒。

**合成来源二：** 虚构项目/ADR-017-重试上限.md，状态“已批准”，2026-10-01 生效：“本 ADR 替代重试策略草案 v1.2。客户端重试等待默认值为 10 秒，上限为 30 秒。”

**评分键：** 正确答案为默认 10 秒、上限 30 秒；参与者须指出 ADR-017 已批准、生效日期较新并明确替代 v1.2 草案。仅挑选日期较新但没核验状态/替代关系，不能计成功。

## 访谈提纲

使用中性追问，先听开放回答，不暗示正面反馈：

1. 你平时如何查这类接口或规范？最近一次大约花了多久？
2. 哪一步最耗时？你通常怎么确认找到的是当前有效版本？
3. 这次哪个答案最难核实？你会如何检查它是否可信？
4. KnowFlow 的来源展示是否改变了你的核验步骤？请描述具体行为。
5. 真实工作中你会在什么任务使用或避开它？为什么？
6. 哪些错误会让你立刻停止使用？这次是否遇到？
7. 未来两周如果没有人提醒，你预计会在哪一天/什么任务再次使用？（记录为预期，不当作复用证据。）
