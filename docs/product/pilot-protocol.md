# 首轮试用验证协议（KF2-002）

- 任务：KF2-002；负责人：M；审阅：Q；日期：2026-10-30（Asia/Shanghai，UTC+8）
- 本协议只提供记录工具与方法；真实试用由项目负责人安排获准参与者后执行。

## 1. 招募条件

- 3–5 位同类用户：日常需查中文技术资料的小型研发团队成员。
- 参与者接触的资料必须有权使用；以匿名或获准文档起步。
- 招募、知情与外部联系由项目负责人负责；Agent 不自行联系外部人员，未获明确授权不发送邀请或消息。

## 2. 匿名任务样本（2 道）

### 任务 A：定位一条技术参数的原文依据

- 任务：从给定资料中找到“某服务超时与重试上限”的数值，并打开原文片段核对。
- 成功标准：找到数值且能打开对应原文片段；或资料中无此内容时明确说明无证据。
- 对照：同一任务先用现有方法做一次，再用 KnowFlow 做一次，分别记录耗时与核验步骤。

### 任务 B：删除后的引用失效验证

- 任务：先就某问题得到带引用的回答；删除被引文档后，再次查询同一问题，确认原引用不可访问、回答不再引用已删内容。
- 成功标准：删除后新请求不检索、不展示、不引用已删文档原文；历史中已显示的来源标注“已删除/不可访问”。

## 3. 访谈脚本（要点）

- 开场：说明目的（验证查找与核验流程）、匿名方式、随时可退出；不诱导评价。
- 任务执行：观察记录为主，不提示答案；记录卡点与原话（匿名化）。
- 事后问题：这次找答案花了多久？哪一步最耗时？你怎么确认答案可信？如果下次遇到同类问题，你会怎么做？
- 不问笼统好评问题（例如“你觉得这个功能好吗”）；好评不能单独作为价值证据。
- 结束：致谢；说明记录用途与匿名处理。

| 字段 | 说明 |
