# KF2-002：首轮用户场景

状态：IN_REVIEW。作者：本会话（Codex，承接 M 线 KF2-002）。场景选择日期：2026-10-30（Asia/Hong_Kong）。审阅目标 SHA 见 docs/tasks/execution-log.md。

## 首轮场景

帮助小型研发团队成员查询中文项目规范和 API 文档，并核对答案对应的原文依据。首轮仅测试个人知识库；不含多人共享、权限角色或跨团队资料。

典型任务：研发人员在实施功能、联调或排查问题时，查找接口必填参数、取值限制、版本差异和已生效规范。资料可能散落在 API 说明、变更记录和项目规范中。当前假设是反复浏览网页、仓库文档或用关键词搜索会增加定位时间；AI 答案若不能定位到正确版本和原文，不能减少核验成本。

## 待验证假设（尚无真实访谈证据）

1. 同类研发人员每周会多次查阅项目规范或 API 资料。
2. 个人知识库能减少找到正确答案和原文依据所需的时间。
3. 展示可访问的原文来源可降低核验成本；不能只凭答案流畅度判断成功。
4. 用户在首次体验后会在两周观察期内主动复用。

## 范围及排除项

- 参与者应正在开发、测试或维护软件，近期确实需要查询中文技术规范或接口说明。
- 试验资料必须由项目负责人确认可合法使用；本包的两道题及其材料为原创合成内容，不能替代真实资料验证。
- 不收集真实项目文档、源码、账号、API 密钥或个人敏感资料；不得把合成示例说成用户观察。
- 不招募、不联系外部参与者。本文件只准备后续用户验证协议，招募与观察由项目负责人安排。

## 结果指标

每道题分别记录基线方法和 KnowFlow 方法的结果，并同时报告人数、任务数和观察天数：

| 指标 | 操作定义 |
|---|---|
| 任务成功率 | 在 8 分钟时限内给出全部关键事实，且指出支持答案的正确有效来源；成功任务数 / 完成任务数。 |
| 依据定位时间 | 从主持人读出任务到参与者找到并展示正确原文出处的秒数；失败按 480 秒记并标注超时。 |
| 核验耗时 | 从首次提出答案到参与者确认或纠正答案的秒数；不知道/未核验单独记缺失原因。 |
| 来源查看次数 | 打开、滚动到或切换一个来源一次计数；重复打开也计入。 |
| 两周复用 | 观察期内主动使用的天数及查询任务数；按天和按任务分别报告。无观察数据时为“未验证”。 |

指标先描述实测分布，不预设产品已达成价值阈值。计时中断、主持人提示、资料未找到和系统失败都要记入备注。
