## 1. 选定的首轮场景

小型研发团队成员在日常工作中，需要从中文技术说明、项目规范和故障记录中，找出一个具体问题的答案，并能打开原文依据核对。

示例问题（假设示例，非真实用户提问）：

- 某内部服务的超时与重试上限是多少？依据在项目规范的哪一段？
- 某次故障的既定处理步骤是什么？依据在哪份故障记录？
- 文档更新后，旧答案是否仍然有效？删除文档后，相关引用是否已不可访问？

核心流程（对应 M1 闭环）：上传真实资料 → 提出一个具体问题 → 查看支持回答的原文 → 更新或删除文档后，查询结果正确变化。

## 2. 现有方法（假设，待访谈核实）

以下为假设，尚未经访谈或观察验证：

- 在团队群聊里问有经验的同事，等待回复；
- 在共享盘、网盘、多个文档中用关键词逐个翻找；
- 凭记忆引用旧版本内容，事后才发现文档已更新；
- 找到疑似答案后，仍需人工翻到原文段落逐句核对。

## 3. 价值假设（假设，待试用验证）

- 一次提问即可得到带原文定位的答案，缩短“找答案 + 核对依据”的总耗时；
- 回答附带文档、索引版本、Chunk 与页码/原文片段，点击可核验；
- 文档更新或删除后，查询结果正确变化，不再引用过期或已删内容；
- 同类问题再次出现时可复用已有答案与证据。

## 4. 衡量指标（定义）

- 任务成功：一次会话内找到答案且能打开原文依据；或在无证据时明确拒答而不误导。成功率 = 成功任务数 / 全部任务数。
- 依据定位时间：从提问到打开第一条可核验原文片段的耗时；对照组为现有人工方法完成同一任务的耗时。
- 核验成本：核验一条回答所需打开的来源数、点击数与人工比对步骤数。
- 复用指标：两周内同类问题再次提问时复用已有答案与证据的比例；重复提问率。
