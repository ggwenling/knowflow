## 残留问题：P2 · 不支持的请求 Content-Type 仍返回 500

**位置：** `services/api/src/main/java/com/knowflow/api/error/ApiExceptionHandler.java:80–84`。

修复新增了 HttpMediaTypeNotAcceptableException（406）处理，但 HttpMediaTypeNotSupportedException（415）仍进入 Exception 兜底，并被改写为 500 / INTERNAL_ERROR。

在候选的临时 Java 副本中，沿用实际 AuthKnowledgeBaseIntegrationTest、真实 PostgreSQL/pgvector、完整 Spring database profile 和实际注册 Controller，只增加以下定向检查：

```java
@Test
void unsupportedRequestMediaTypeDoesNotBecomeServerError() throws Exception {
    var result = mockMvc.perform(post("/api/v1/auth/register")
                    .contentType(MediaType.TEXT_PLAIN)
                    .content("synthetic request"))
            .andReturn();
    assertThat(result.getResponse().getStatus()).isEqualTo(415);
}
```

**实际：** 定向测试 1 项失败，expected 415 / actual 500；响应为 draft.4 的统一错误体，code=INTERNAL_ERROR。它不是数据库连接、认证或密码验证失败，而是 JSON 接口不支持 text/plain 的框架请求错误。

用户客户端使用错误的 Content-Type 时被报告成服务器故障，仍会误导调用方与运行诊断。仅为 406 增加分支没有解决这项验收要求。

**修复验收：** 在 Java 错误处理边界保留 415 及框架必要响应头，返回统一脱敏客户端错误体；补充实际注册/JSON 接口的该负例，维持 404、405/Allow、406、request ID 与真实未知异常 500 的已有检查。不要通过放开 text/plain 请求或放宽断言掩盖问题。

定向复现只修改了 `/workspace/scratch/q-main-media-probe` 的测试副本，未编辑合并候选或作者分支。实际命令：

```sh

  '-Dtest=AuthKnowledgeBaseIntegrationTest#unsupportedRequestMediaTypeDoesNotBecomeServerError' test
```
