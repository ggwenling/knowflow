## 问题证据与修复要求

### R2：普通真实适配器工厂通过启动检查，但运行时先扣预算再拒绝

`DeepSeekAdapter` 和 `SiliconFlowEmbeddingAdapter` 新增的是**类属性**。使用 `adapter_factory=lambda: DeepSeekAdapter(settings, client)` 或 `functools.partial(...)` 注入必要构造参数时，工厂函数本身没有这个属性。`_reserve()` 第 42 行因此选择外层预留；直到第 66 行才发现返回的对象具有底层预算边界，关闭对象并抛出 `AUTHORITATIVE_BUDGET_BOUNDARY_REQUIRED`。

`EvaluationFactories.preflight()` 验证价格与上界声明，但不检查这个新增工厂协议，因而正常通过。README 第 9 行列出的工厂配置也未说明必须给 callable 另行添加该属性。本轮新增测试在 `services/ai/tests/test_provider_budget.py:141` 专门手工设置这个属性，只覆盖了能工作的特殊配置。

独立离线复现通过实际 `EvaluationFactories` 创建包装器，使用同一个真实 SQLite 账本、有效合成 price / policy / bound evidence，以及真实产品适配器 + `httpx.MockTransport(503)`。每种操作重复两次，沿用同一个产品 request ID；表内预留金额为两次操作合计：

| 工厂配置 / 操作 | preflight | Mock HTTP 次数 | paid reservations | reserved microyuan | 结果 |
| --- | --- | --- | --- | --- | --- |
| 普通 lambda / embed | 通过 | 0 | 2 | 20,000 | 两次均 `AUTHORITATIVE_BUDGET_BOUNDARY_REQUIRED` |
| 普通 lambda / generate | 通过 | 0 | 2 | 24,096 | 两次均同上 |
| 普通 lambda / stream | 通过 | 0 | 2 | 24,096 | 两次均同上 |
| 显式标记 / embed | 通过 | 2 | 2 | 20,000 | 两次均供应商合成 503；每次一条预留 |
| 显式标记 / generate | 通过 | 2 | 2 | 24,096 | 同上 |
| 显式标记 / stream | 通过 | 2 | 2 | 24,096 | 同上 |

另对三种操作将显式标记工厂的环境账本改成不同路径，均在 HTTP 前得到 `BUDGET_LEDGER_CONFIGURATION_MISMATCH`，两边没有产生付费预留。这部分保护有效。

这里没有发现真实请求绕过底层预算，也没有把失败 HTTP 保留一次预留视为错误。问题是此前支持的普通工厂现在完全无法执行，而且**确定没有进入适配器调用的配置错误**仍不断占用不可退款预算；这是本轮新增的兼容性与记账回归。

修复要求：在写入外层预留之前确定并验证权威边界，使普通 lambda / partial 包装真实产品适配器时也可正常工作，并保持裸适配器保护。如果选择强制显式协议，则必须明确文档、在 preflight / 配置校验阶段拒绝不合规配置，且不得先留下预留后才报配置错误。增加普通工厂经 `EvaluationFactories` 的组合测试，核对启动校验、HTTP 次数、预留次数及失败重试。

### R5：新增负例与现有 CI 的测试运行器不匹配

现有 `python-contract` job 先用 `uv run --project services/ai` 执行服务测试，最后另用裸 `python -m unittest discover -s evaluation/smoke -p 'test_*.py' -v`。uv 项目虚拟环境里的 pytest、httpx、psycopg 不会因此安装到裸 Python。新文件在模块顶层导入 pytest，并加载间接导入 httpx / psycopg 的 E2E 脚本，使原本可独立运行的标准库测试目录引入了项目依赖。

本地执行该裸 Python 命令，19 个 `SmokeTests` 通过，但额外出现一个 loader error：

```text
ImportError: Failed to import test module: test_e2e_evaluation
ModuleNotFoundError: No module named 'pytest'
Ran 20 tests
FAILED (errors=1)
```

用仓库 Python 3.12 加 `-S` 隔离 site-packages 后也复现同一导入错误，说明问题不依赖本机系统 Python 的版本。在依赖齐全的服务虚拟环境中执行同一 unittest discovery 命令，结果为 **19 passed**；新增的两个模块级 `def test_*` 函数均未被 unittest 收集。现有服务 pytest 命令只指定 `services/ai/tests`，也不会收集这个新文件。

修复要求：把新增测试接入 CI 实际执行的运行器与依赖环境，例如移入已有服务 pytest 测试目录，或相应调整 smoke 测试命令 / 测试形式和依赖边界。验证 CI 中的等价命令，确认两个新断言确实执行；仅安装 pytest 或仅让 unittest discovery 不再报错不足以关闭此项。
