### Q-JP01-01 · P1 · 两分支契约版本不一致，当前组合不能完成健康联调

**位置：** python `services/ai/src/knowflow_ai/protocol.py:10–11`、`27–32`；java `services/api/src/main/java/com/knowflow/api/ai/AiInternalHealthClient.java:39–44`。

**性质：已知集成阻断，本轮独立确认；不是将严格版本检查本身报告为缺陷。** Java 当前发布并要求 `0.2.0-draft.4`，Schema SHA-256 为 `ca66965155ff3e23209de18a44823a74429a8590df5adbd458571ef52b524e41`；Python 固定 `0.2.0-draft.2` 和旧 Schema SHA-256 `edc9ada0bb5de23ddf69f96c9172b3fc3719f4b3111d5d35718f2717efae8087`。

1. Python 使用 Java 当前 Schema 文件启动：`create_app` 抛出 `ConfigurationError: CONTRACT_HASH_MISMATCH`，无法启动。

所以两边各自回归通过或旧版 WebClient 直连成功，都不足以批准当前两个目标的 JP-I1。A 已在联调记录中正确标为 `BLOCKED_CONTRACT_VERSION`，本次没有发现作者将此阻断伪报为兼容通过。

### Q-JAVA-01 · P2 · 不支持的 Accept 类型仍被当作 500 服务故障

**位置：** java `services/api/src/main/java/com/knowflow/api/error/ApiExceptionHandler.java:64–68`。

虽然上轮 404/405 已修复，兜底 `Exception` 处理仍把其他 Spring HTTP 客户端异常写成 `500 INTERNAL_ERROR`。独立启动本次构建的 JAR 后，请求：

```sh
curl -i -H 'Accept: text/plain' http://127.0.0.1:<实际端口>/actuator/health
```

实际返回 500 / INTERNAL_ERROR；这是响应类型不受支持的请求，应保留 406。普通 JSON 健康请求仍返回 200，因此不是进程故障。客户端内容协商错误会被监控或调用方理解为服务器失败；增加业务端点后仍会受同一全局处理器影响。

**修复验收：** 为框架已确定 HTTP 状态的异常保留状态和必要响应头，继续输出统一脱敏错误体；真正未知的服务异常才落到 500。至少补充上述 406 回归，并覆盖新增 JSON API 的不支持 Content-Type 情形；后者本轮未单独发 HTTP 请求，不记作已执行的 415 复现。维持已修复的 404、405/Allow、request ID、认证和日志脱敏测试。

### Q-PARSE-01 · P2 · Unicode 空白文档被接受为有效文本

**位置：** python `services/ai/src/knowflow_ai/parsing.py:76–82`。

TXT/MD 的空内容判断只去掉 BOM、ASCII 空格、TAB、CR、LF。仅含不换行空格 U+00A0、中文全角空格 U+3000，或 VT/FF 的 UTF-8 文件仍返回成功的 `ParsedDocument` 和非空块；这些字符串的 Python `isspace()` 均为 true。当前 PDF 分支用 `text.strip()` 判断空页，TXT/MD 的行为也与之不一致。

复现示例，在 Python 分支的锁定环境执行：

```python
from knowflow_ai.parsing import parse_document

parsed = parse_document(
    "\u3000".encode("utf-8"), format="txt",
    document_id="doc-test", content_version_id="content-test", file_id="file-test",
)
assert parsed.characters == 1  # 当前成功，但文件只有空白，无可用内容
```

解析组件因此会把没有可用文字的文件交给后续分段/索引，而不是返回已定义的 EMPTY_DOCUMENT。当前没有启用上传/索引路由，本轮不声称已经发生线上空索引发布。

**修复验收：** 空内容判断应覆盖 Unicode 空白及 BOM，同时原样保留真正非空文本的 BOM、CRLF 和码点偏移。为 TXT/MD 增加 U+00A0、U+3000、VT/FF、BOM 与空白组合的负例，并保留包含这些字符及正常正文的正例，确认返回文本和原文定位不变；不要通过归一化正文修复这个判断。
