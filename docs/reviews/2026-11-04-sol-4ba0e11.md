## 发现列表

### 1. [P2] INSERT 未抛异常不等于成功预留，RAISE(IGNORE) 触发器仍被放行

- 位置：`evaluation/collector/real_service.py:69-84`。
- 新探针在事务中插入两种预留、删除探针行并回滚，但没有读取或核对实际插入的行。SQLite 的 `BEFORE INSERT ... RAISE(IGNORE)` 会跳过插入且不抛异常，随后 DELETE 删除零行也不抛异常，因此 `_assert_shared_ledger_ready()` 正常返回，`create_real_app()` 放行不可记录预留的共享账本。
- 合成复现：先用 `BudgetLedger` 创建标准账本，再执行以下 SQL，然后以测试中的有效配置启动应用：

  ```sql
  CREATE TRIGGER reject_insert BEFORE INSERT ON reservations
  BEGIN SELECT RAISE(IGNORE); END;
  ```

- 实际结果：启动成功。通过 guarded factory 分别调用 embedding（`["hello"]`）与 LLM（`{"source_id": "s1", "text_content": "t"}`），仅使用返回 HTTP 500 的 `httpx.MockTransport`。两次调用均返回 `ProcessingError(code="MODEL_FAILURE")`，捕获 URL 为 `https://api.siliconflow.cn/v1/embeddings`、`https://api.deepseek.com/chat/completions`；之后共享账本的 `paid_reservations == 0`、`reserved_microyuan == 0`。相同请求在正常账本上得到 2 笔预留、累计 202048 微元。
- 对 `zero_price_reservations` 安装同类 IGNORE 触发器，启动也成功；该分支本次只动态验证了启动行为。
- 影响：前次发现 1 尚未完全关闭。异常式拒绝写入已能 fail-closed，但静默拒绝写入仍被误判为可预留；在上述损坏账本上，请求会越过预留入口并到达模拟供应商，却不持久记账。底层 `BudgetLedger.reserve()` 未检查插入结果是既有行为，本次新增的启动探针仍未拦截这种状态。
- 建议：在回滚前读取并核对每个探针行及其完整字段，确认写入真实发生；不应仅以 SQL 无异常作为成功证据。增加 paid/zero 两张表的 `RAISE(IGNORE)` 回归，断言启动错误完整等于 `EVALUATION_SERVICE_NOT_READY: KNOWFLOW_BUDGET_LEDGER_PATH`，且账本无持久变化。
