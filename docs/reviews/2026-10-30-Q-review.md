## 修复要求

### Q-003-01 · P2 · 返回模型不符仍判冒烟成功

**位置：** `evaluation/smoke/model_smoke.py:221–222, 237–241`，适用 python 交付目标及其 KF2-003 前序实现。

当 Embedding 或 LLM 的响应 `model` 明确不同于请求配置时，代码只记录 `provider_model_matches_request=false`，随后仍写入 `PASSED` / `LIVE_SMOKE_PASSED` 并退出 0。用两条合法二维向量、一个通过现有事实检查的合成中文回答及不同的模型标识即可离线复现。这会让代理误路由或模型替换后的复测仍作为“所选模型可用”证据，也没有保留实际响应模型名供追查。

**复现：** 从原工作区执行：

```sh
python docs/reviews/repro_model_identity.py --repo /workspace/scratch/knowflow-q-review
```

三种场景（仅 Embedding 不符、仅 LLM 不符、两者均不符）都返回成功。脚本只使用内存响应和合成凭证，不调用供应商。

**修复验收：** 分别记录经长度/字符约束的请求与响应模型标识；明确不符时不应直接成功。若供应商会返回等价版本名，定义可审查的别名映射；缺少响应模型时单独表达未验证，不能与明确不符混为一类。补充两个端点不符的负例，Embedding 不符时停止后续付费请求，并保留正常配置通过的测试。

现有真实证据中的两个匹配标志均为 true，本问题不证明已有真实调用用了错误模型；它指出验证工具的成功判定存在漏检。
