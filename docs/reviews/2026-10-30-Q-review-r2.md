## 新发现

### Q-006-01 · P2 · 统一异常处理将正常 HTTP 客户端错误改成 500

**位置：** `services/api/src/main/java/com/knowflow/api/error/ApiExceptionHandler.java:27–31`。

`@ExceptionHandler(Exception.class)` 对 Spring MVC 的路由不存在、方法不支持等异常也一律返回 `500 INTERNAL_ERROR`，覆盖框架原本的 404/405 语义。独立启动构建后的 JAR，真实 HTTP 请求得到：

| 请求 | 实际结果 | 应有语义 |
|---|---|---|
| `GET /actuator/health` | 200，`UP` | 健康检查正常 |
| `POST /actuator/health` | 500，`INTERNAL_ERROR` | 方法不支持，应为 405 |
| 携带正确内部 Bearer 的 `GET /internal/route-does-not-exist` | 500，`INTERNAL_ERROR` | 路由不存在，应为 404 |
| 无内部凭证的同一路径 | 401，`UNAUTHENTICATED` | 认证边界正常 |

接口拼写错误或调用方法错误被表现为服务故障，会误导客户端与监控。现有测试覆盖认证错误，但未覆盖这些 MVC 异常。

**修复验收：** 为路由不存在、方法不支持等已有 HTTP 状态的框架异常保留状态并输出统一脱敏错误体；真正的未知服务异常再返回 500。补充上述 404/405 的实际路由测试，核对响应头与错误体仍使用同一 request ID；保留现有认证、健康脱敏及未知异常处理检查。无需开放业务路由。

### Q-006-02 · P2 · 启动校验放过带换行的共享密钥，随后所有内部调用失败

**位置：** `services/api/src/main/java/com/knowflow/api/config/AiServiceProperties.java:48–53`。

`!internalSharedSecret.isBlank()` 只能排除全部为空白的字符串，不能排除有效字符中混入 CR/LF、空格或其他非法 Bearer 字符。以 40 个 `A` 后接一个换行作为合成配置，已独立确认：

- 配置校验方法返回 true；真实 JAR 进程成功启动，健康检查返回 200。
- 使用当前 `AiHttpClientConfiguration` 创建 WebClient 并请求本地 stub，抛出 `WebClientRequestException`，底层为 `IllegalArgumentException`，因为 Authorization 值含非法换行。

复制密钥或环境注入时多出的换行因此不会在部署时被发现，服务显示健康，直到内部调用才持续失败，与本任务“非法配置启动即明确失败”的要求不符。

**修复验收：** 明确定义共享 Bearer 密钥可用字符集，启动时拒绝 CR/LF、其他控制字符及不允许的空白，保留长度检查，且不在异常消息中输出原值。增加带有效前缀的 CR/LF、空格、制表符负例及正常随机密钥正例；校验失败应发生在启动阶段，不能靠请求失败代替。不要静默 trim 或修改共享密钥。

复现使用完全合成密钥、loopback stub，未调用 B 服务或外部供应商。Java 探针源码见 [QSharedSecretProbe.java](QSharedSecretProbe.java)；HTTP 观察和探针结果见 [本轮证据](2026-10-30-Q-evidence-r2.json)。
