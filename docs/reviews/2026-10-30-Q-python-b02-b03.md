## Q-B03-01 · P2 · 返回的 Provider 元数据违反内部 EmbeddingResult Schema

**位置：** `services/ai/src/knowflow_ai/embedding.py:158–160`。

适配器把供应商 `data` 行排序后原样塞入内部结果。硅基流动官方响应示例的行包含 `object: "embedding"`、`index`、`embedding`，而当前共同消费的 draft.4 `EmbeddingResult.data.items` 仅允许 index/embedding，且 `additionalProperties=false`。

用该正常 Provider 形状、正确模型、1 条有限非零 1024 维向量执行真实适配器代码，会成功返回；随后用本项目 `ContractConsumer.validate("EmbeddingResult", result)` 校验，得到 `INVALID_MESSAGE`。现有成功测试的 Mock 行省掉了供应商的 object 字段，因而没有覆盖这个差异。真实冒烟也只检查向量和摘要，没有验证返回值是否符合内部 Schema。

这会在后续按严格共享契约消费适配器结果时拒绝正常模型响应。本轮没有业务索引路由，因此不声称已经造成线上索引失败。

**修复验收：** 在 Provider→内部结果边界显式映射/白名单化行字段，保留已验证的 index 和 embedding，不能把供应商新增元数据直接带入严格内部消息。增加包含标准 object 及其他 Provider 元数据的成功样例，并对完整适配器返回值执行当前共享 EmbeddingResult 校验；保留错误模型/维度/索引的拒绝测试。共享 Schema 仍由 A 单写，不应为迁就第三方字段而静默放宽。

官方来源：[SiliconFlow Embeddings API](https://docs.siliconflow.cn/docs/api/embeddings-post)。本次独立读取的公开示例明确包含 `"data": [{"object": "embedding", "embedding": [0], "index": 0}]`；该示例用于字段形状核对，维度测试使用合成 1024 维数据。

## Q-B03-02 · P2 · 注入客户端使超时和禁重定向约束失效

**位置：** `services/ai/src/knowflow_ai/embedding.py:99–103,119–124`。

超时与 follow_redirects=False 仅在构造内部 AsyncClient 时设置；传入调用方拥有的客户端后，实际 stream 请求没有覆盖这两个参数，会沿用客户端自己的设置。该类公开支持客户端注入，但其安全/请求限制因此与默认构造路径不同。

独立离线复现：

- EmbeddingSettings.timeout_seconds=0.1，注入 AsyncClient(timeout=60)。实际请求 extensions 的 connect/read/write/pool 超时均为 60，而非所配置的 0.1；配置限制没有生效。本结论仅检查 HTTPX 传输超时，不把它误写成已验证的总期限行为。
- 注入 AsyncClient(follow_redirects=True)，第一跳返回 307 到 `https://outside.example/receiver`。适配器发起第二个 POST 并在收到合成向量后返回成功，违背其“禁重定向、固定 Provider 主机”约定。第二跳 Authorization 已被 HTTPX 剥离，但原始 input 正文仍完整转发到该主机。

上述所有请求由 MockTransport 截获，没有访问外部接收地址，也没有使用真实密钥。默认由适配器自行构造的客户端禁重定向行为仍正常；问题触发条件是复用带不同配置的注入客户端。目前模块未接入业务处理路由，不能据此宣称现有生产资料已经外泄。

**修复验收：** 在每次 stream 调用处显式应用本适配器的超时和 follow_redirects=False，或采用同等可验证且不影响共享客户端其他使用者的方式。增加注入 timeout=60 / follow_redirects=True 客户端的负例：仍使用 Settings 的超时；307 只发一跳并按固定错误拒绝，原始 input 不得被转发；保持调用方客户端所有权和取消传播行为。
