# 真实 RAG 采集与评分设计（待实现）

Sol High 基于 b7e83c8 独立规划。此文不代表采集、真实模型调用或质量验收已经完成。

评测专用服务使用真实 provider、真实只读检索器及 Java 写入/授权链路。采集器注册、建库、上传、等待 READY、发起问答，并以唯一 request ID 关联 trace。建立数据集文档和运行时 document/content/index ID 的映射并核对来源哈希。检索器包装调用一次 top_k=10，保存完整顺序，只向生成器返回前 5；不得将最终引用当作完整检索结果。trace 缺失、ID 重复或映射不符时拒绝输出正式预测。

版本化 v2 预测绑定代码和 schema SHA、数据集指纹、运行配置及模型身份；每题区分 answered、refused、error，记录实际回答、引用、耗时及脱敏错误。人工审核包应展示回答和各引用的原文、绑定预测与回答哈希，逐项记录答案支持及引用语义判断。旧 v1 仅供历史分析，缺少语义判断或实际回答时正式质量门 incomplete。保留现有 Recall@5 的证据跨度定义、MRR@10、来源跨度重合指标与非零退出规则；新增语义引用准确率、执行错误率及可回答题误拒答率。错误不能伪装拒答，缺题、零分母、未审核或缺失 trace 不能通过。

Java 会依据问题 ID 和内部 source ID 派生公开 UUID 并改写答案引用标记。采集器必须将同次检索 trace 的内部来源映射到与公开回答一致的 source ID 命名空间；逐次出现的标记都须绑定前五项检索结果及独立审核项，重复出现也逐次审核。缺失、额外、未知或未审核的标记不得通过正式质量门。

预算需覆盖 worker 索引 embedding、问答 embedding 与生成，包括重试及重派。评测专用入口使用单一持久化账本，在每次请求前按核验价目、输入上界和最大输出预留人民币费用；超时或 usage 缺失保留预留。总额不得超过用户批准的 10 元，价目、汇率或费用上限无法可靠确定时停止。不能将调用后的 usage 汇总称作硬预算。

用户私有盲题、答案、trace 和审核原文只在受控环境保存，公开报告仅含版本、指纹、指标、分母及脱敏失败类型。离线评分可从已保存数据复跑；外部模型别名和 provider 的不确定性不保证重复调用产生逐字相同答案。当前评分器以 TXT/Markdown 字符区间为基础，PDF 评分需单独设计；评测 trace 也可能带来额外延迟，应在报告注明。
