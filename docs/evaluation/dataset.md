# KF2-010 原创合成种子资料 v1

状态 IN_REVIEW（开发验证通过），依赖 KF2-002/003 为候选已交付，用户授权按 JP-01 不等待复核继续。此处不包含真实用户结果或生产文档。

语料位于 evaluation/data/seed-v1：10 份完全原创的「青竹」虚构项目文档（TXT/MD），15 道中文种子问题；12 道有答案、3 道资料不足需拒答，覆盖参数、同义问法、规范冲突、多来源、权限、来源位置与无答案。演示的 6 MiB、360 码点、18 秒等数字只属于虚构语料，不能当 KnowFlow 生产限制。与 KF2-002 的两道试填分开，不拿试填扩充真实评测。

## 来源、权限与版本

文本由本次作者独立编写，生成脚本内包含完整原创原文及参考标注；这些新语料及参考标注按 CC0-1.0 贡献，可复现、可随代码公开、可供外部模型合成冒烟。项目其他代码和第三方依赖不受此数据许可声明影响。没有下载他人规范、用户文档、个人资料或密钥。此许可和合成属性记录在 manifest 中，不表示真实用户场景已得到验证。

manifest 记录路径、原始 UTF-8 SHA-256、文件字节数/码点数、内容版本标识、格式、来源/许可和外部 API 使用范围。questions 逐题记录答案要点（reference_answer）、原文 quote、内容版本、0 起右端不含的 Unicode 码点区间及 1 起行号。每题按所有关键事实及版本依据评分，缺事实或来源不匹配记失败。无答案题 evidence=[]，不能编造 Chunk 或把其他资料的知识补成依据。

## 标注与划分

先读取每份原文，再独立核验 15 题的答案及摘录；程序进一步逐项验证所有引用、版本、哈希、行号和码点。q04 同时要求草案状态、已批准 ADR 的生效与替代关系及最终数值，只有数字正确不能算成功。q06 要求身份来源与统一 404 两项；q07 要求唯一发布者、全部核验项及事务切换；其余题按参考答案列出的事实核对。q12/q13/q15 应说明资料不足而非猜测账单、OAuth scope 或 GPU。

开发集 12 题、留出集 3 题（q09/q14/q15），leakage_group 相同的问题不得跨分区；来源定位的两题作为一组留出。留出参考答案也在仓库中，因此只是流程上的留出，不宣称盲测或无泄漏；后续 KF2-037 应由未参与调参者追加真正独立的样本并扩到 60 题。此处无模型得分、用户分数或质量达标结论。15 题均已由作者按原文核对，不代表 Q 独立复核已完成。

复现（从仓库根）：

```sh
python evaluation/data/tools/build_seed.py
python evaluation/data/tools/validate_seed.py
```

生成脚本和数据都纳入版本；同一脚本重建应得到相同 manifest、问题与文件哈希。修改资料必须重生成内容版本和引用；不得沿用旧偏移。测试覆盖正常集及篡改原文、错误范围/版本和分区泄漏负例。PDF 解析边界样本在 KF2-016 的服务测试目录单独保存，不能把 PDF 解析器成功当种子题检索/问答成功。
