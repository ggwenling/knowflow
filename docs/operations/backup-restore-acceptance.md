## 需完成的闭环

1. 在第一套环境中注册两个用户；由用户 A 创建知识库、上传资料并等待活动索引 READY，完成一次带来源的问答。确认用户 B 不能访问 A 的文档、来源和原文。
2. 停止应用写入并确认索引与清理任务已静止，建立同一一致性窗口的 PostgreSQL 数据库备份及 MinIO 对象备份。记录对象和备份摘要；凭据单独管理，不写入证据。
3. 在第二套空白环境恢复数据库、对象及必要非秘密配置；重新注入第二环境所需凭据，验证数据库角色、迁移历史和对象访问。备份与恢复操作需在隔离环境中验证，不对现有用户卷执行。
4. 验证恢复后文档与原文逐字节一致，活动索引可检索，历史回答和来源指向正确版本，用户 B 仍无法越权访问；同时运行新问答，核验其真实引用来源。
5. 模拟升级失败并证明不会破坏恢复副本；只记录实际验证的回滚方式，不承诺数据库降级。
6. 核验并清理本次创建的环境、临时备份和凭据，保留仅含哈希、环境、步骤与结果的脱敏证据。清理失败须保留标识并报告，不能标通过。
