# 限流与资源边界（2026-11-08）

状态：**部分实现；边缘限流与生产参数仍缺证据**。

## 1. 已有边界

| 边界 | 现状 | 证据 |
|---|---|---|
| 问答并发 | Java/Python 共用每进程并发上限，默认 4，`KNOWFLOW_QUESTION_MAX_CONCURRENT=1..32` | 计划与测试记录 |
| 请求体 | 同源代理上限 9 MiB | `apps/web-v2/src/app/api/v1/[...path]/route.ts` |
| 上传 | 8 MiB、PDF 200 页、文本 200,000 码点（开发上限） | `contracts/api-draft.md`、上传 UI 文案 |
| 问答来源 | 最多 5 条 | `services/api.ts` 校验 |
| 索引队列 | 有界队列，满载拒收 | Python worker 计划/测试记录 |

## 2. 缺口

| 缺口 | 风险 | 建议 |
|---|---|---|
| 边缘/网关 per-IP 限流 | 单 IP 刷注册、登录、问答 | 反向代理/网关加令牌桶；对 `/auth/*` 与 `/questions*` 分开限流 |
| 注册枚举防护 | 通过 409/响应差异枚举邮箱 | 统一响应时序与文案；加验证码或邀请制（需产品决定） |
| 登录暴力破解 | 撞库 | 失败计数、指数退避、告警 |
| SSE 并发/连接时长 | 资源占用 | 每用户并发上限、最长连接时间、断开清理 |
| 上传频率 | 存储与索引压力 | 每用户/每库配额与速率 |
| Linux 解析资源 | 大 PDF/异常文本内存 | cgroup/进程上限、超时、抽样压测 |
| 生产参数 | 默认 4 并发未压测 | 按容量测试后设定，记录证据 |

## 3. 验证计划

1. 对 `/api/v1/auth/login` 与 `/api/v1/knowledge-bases/{id}/questions/stream` 做阶梯并发（1/4/8/16），记录 429/503、p95、错误率。
2. 验证限流响应带 `Retry-After`，且不泄漏内部实现。
3. 验证 SSE 断开后上游取消、无迟到写入。
4. 对 8 MiB 上传、200 页 PDF、超长文本做拒绝测试。
5. 生产环境重复以上测试，记录实例规格、连接数、内存。
