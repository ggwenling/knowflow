## 本地验证

使用 Python 3.12；先执行 `python -m pip install -r contracts/requirements-validation.txt`，再从仓库根执行：

```bash
python contracts/validate.py
git diff --check
```

检查 Schema 本身、样例与字段/格式限制。**结构合法不代表调用被授权**：旧租约、重复完成和删除竞态需要 Java 在数据库事务中验证；目前没有运行服务或数据库测试。失败报文的结构校验不能当作权限/状态机已经实现。

`jsonschema` 默认可能未安装日期时间格式检查器；本脚本要求 RFC 3339 检查器可用，缺失时直接失败，避免无时区时间被静默接受。

## 草案约定

- JSON 字段使用 `snake_case`；对外 API 不接受客户端自报 `owner_id` 或内部可信范围。
- 时间使用带时区的 RFC 3339；服务器时钟决定租约有效性。UUID/标识符不承担授权职责。
- 请求 ID 由 Java 生成，内部调用沿用；外部传入值只可作为受长度限制的诊断关联信息。
- 内部服务认证与执行令牌分离：服务凭证证明调用方，执行令牌、递增 fencing 值、数据库状态共同限制某次执行。示例令牌仅为不可用占位文本，禁止在日志输出真实值。
- Schema 的 `writeOnly` 是工具提示，不是自动脱敏；实现日志必须主动过滤凭证、问题/文档全文与提供商密钥。
- 非存在、非所有者、已删除的外部资源均返回无资源细节的 `404 RESOURCE_NOT_FOUND`；未认证返回 `401`。内部范围校验失败可使用 `403 SCOPE_DENIED`，不将内部细节透传浏览器。
- 更新后的旧引用仍绑定旧内容/索引版本；已删除和已清理的历史来源只返回状态，不返回原文、定位或可下载地址。

## 冻结清单与变更流程

1. A 收到并核对 V1.1；完成映射与冲突处理记录。
2. M 提供 KF2-002 场景、页面字段及错误态需求；B 提供 KF2-003 的模型配置、向量维度、上限、隐私与 AI 接口建议。M 的 KF2-005 明确服务与配置约定。
3. A 补齐 OpenAPI、完整请求/响应、错误映射、SSE 及历史契约；落实迁移与受限角色。当前文档仅是候选接口目录和核心消息 Schema。
4. B/M 确认同一版消费方式；Q 审阅权限、过期执行、并发删除/发布等高风险场景，结论绑定提交。
5. A 发布明确的冻结版本；变更由提议者记录原因、兼容性和影响任务，A 单独修改公共契约，B/M 确认后由 Q 复核，再更新版本。

无法达成上述条件时保持草案，不以通过 JSON 校验替代冻结或真实联调。
